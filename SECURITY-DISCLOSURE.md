# OpsForge Security Disclosure Policy

OpsForge follows a responsible disclosure process to ensure vulnerabilities are reported and remediated safely.  
This document defines how contributors and external parties should disclose security issues.

---

## 🔐 Responsible Disclosure Guidelines
- Report vulnerabilities privately — do not disclose publicly until remediation is confirmed.  
- Use GitHub Issues with the **“Security Disclosure”** label for private reporting.  
- Provide detailed reproduction steps, affected modules, and potential impact.  
- Respect module boundaries:
  - **BuildMate** → software-only (construction SaaS workflows, compliance logging, project ops).  
  - **DroneOps** → all drone hardware and aerial intelligence (surveying, surveillance, counter‑drone, telemetry).  

---

## 🚫 Prohibited Actions
- Public disclosure of unpatched vulnerabilities.  
- Exploiting vulnerabilities for unauthorized access or commercial gain.  
- Mixing drone hardware references into BuildMate (software-only).  
- Circumventing CI/CD validation or audit logging.
